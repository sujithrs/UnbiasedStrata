# On-disk formats written by the tools

## Purpose

This page is the reference for every file the upstream Python tools write and the engine (or another tool) reads.
Upstream's own format document (`docs/pack-format.md`, cited in `tools/strata_pack.py:4` and
`tools/strata_tokenizer.py:6`) is not in the published tree, so the formats below are re-derived from the writers
and checked against the engine's readers.

A **pack** is the directory the engine loads with `--pack`: an index of the non-expert ("dense") tensors, the float
tensors themselves, and a description of where the routed experts live. Upstream has two kinds:

| Pack kind | Writer | Experts | Used by setup for |
| --- | --- | --- | --- |
| Native pack | `tools/iq_pack.py` | read from the model's GGUF shards in place (optionally copied into `experts.bin`) | every model except the case below (`setup.py:4185-4189`) |
| Canonical Q2_0 pack | `tools/strata_pack.py` + `tools/pack_index.py` | re-laid-out into a 1,382,400-byte-per-expert arena (`experts.bin`) | Q2_0 of the original model on an AVX-512 CPU (`setup.py:4175-4181`) |

Beside the packs, the tools write the MTP draft layer's runtime directory, the expert-cache profile, the draft
vocabulary subset, two one-tensor GGUFs and test fixtures. Terms such as MTP, PLE and expert cache are defined in
the [glossary](../guides/glossary.md).

Files covered: the outputs of `tools/iq_pack.py`, `tools/strata_pack.py`, `tools/pack_layer.py`,
`tools/pack_index.py`, `tools/strata_tokenizer.py`, `tools/mtp_fetch.py`, `tools/mtp_pack.py`, `tools/mtp_rt.py`,
`tools/make_profile.py`, `tools/draft_vocab.py`, `tools/embd_bf16_pack.py`, `tools/ple_fp8_pack.py`,
`tools/iq_fixture.py`, and the image-embedding file of `tools/vision/strata_vision.cpp`.

## 1. Native pack (`tools/iq_pack.py`)

```
<pack>/
  index.txt               non-expert tensor table (19 columns)          published together, under .tmp names first
  dense.bin               float tensors in the engine's form            "
  conversions.json        every converted tensor (schema 1)             "
  compat-bf16.json        only with --compat-bf16
  extra.bin               only with --base
  tokenizer/              from strata_tokenizer.py (if missing)
  native_experts.txt      the expert map; WRITTEN LAST = completion marker
  experts.bin             optional (--experts-bin)
  experts.bin.src.json    what experts.bin was cut from
```

### 1.1 `index.txt` (native)

Written by `write_index` (`tools/iq_pack.py:363-376`):

```
# strata pack index v3 -- generated by tools/iq_pack.py (native experts) from <shard 1 file name>
# align 64 pool <arena bytes> tensors <rows>
<name> <file> <kind> <src_off> <src_bytes> <dst_off> <dst_bytes> <ne0> <ne1> <code_bits> <code_bias> <group_elems> <codebook> <has_offset> <codes_bytes> <scales_bytes> <offset_bytes> <scales_fp16> <act_kind>
```

The 19 columns are the canonical pack's (section 2.4); the engine parses exactly 19 fields and refuses a row with
any other count (`src/core/weights.cpp:165-177`). What `iq_pack.py` puts in them:

| Row type | file | kind | src_off / src_bytes | dst_bytes | code_bits / bias / group | rest |
| --- | --- | --- | --- | --- | --- | --- |
| Quantized tensor served natively from the GGUF (`--native`) | 0 | 0 | 0 / 0 | 0 | 8 / 0 / 32 | 0 (`iq_pack.py:306-309`) |
| Float tensor in `dense.bin` | 0 | 2 (F32), 3 (F32 narrowed to F16 by the loader), 4 (BF16), 5 (F16) | offset and length in `dense.bin` | bytes in the engine | 0 / 0 / 1 | 0 (`iq_pack.py:327-332`) |
| BF16 tensor in `extra.bin` (`--base` only) | 3 | 4 | offset and length in `extra.bin` | same | 0 | 0 (`iq_pack.py:405-409`) |

`dst_off` is recomputed for every row by `write_index` as the running sum of `dst_bytes` rounded up to 64
(`iq_pack.py:364-367`); the header's `pool` is that total. The engine maps file ids 0..3 to `dense.bin`,
`embd.bin`, `experts.bin`, `extra.bin` (`src/core/weights.cpp:64-71`) and turns kinds 4 and 5 into the engine forms
of kinds 1 and 3 with a raw 16-bit source (`src/core/weights.cpp:180-185`).

Kind 3 exists for one tensor: `ple_conv1d.weight` is read by its kernel as F16, and an F32 source is stored as F32
in `dense.bin` with `dst_bytes` = half its size; the loader narrows it with round-to-nearest-even
(`iq_pack.py:258-262`).

### 1.2 `dense.bin` (native)

The tensors the engine reads from the pack rather than the GGUF, each padded to 64 bytes (`iq_pack.py:329-332`).
The form each tensor must have is the `FORM` table (`iq_pack.py:73-86`, keyed by the name without `blk.N.`):
routers, hyper-connection projections, indexer projections, `ssm_alpha`/`ssm_beta` and the PLE key/value are BF16;
the q/k norms, hyper-connection norms, indexer norms, PLE norms, `ssm_a`, `ssm_conv1d`, `ssm_dt.bias` and
`ssm_norm` are F32; `ple_conv1d` is F16. A float tensor not in `FORM` is written as stored. The conversion rules
are in [pack-builders.md](pack-builders.md).

### 1.3 `native_experts.txt`

The expert map and the pack's completion marker (written last through `native_experts.txt.tmp` and a rename,
`iq_pack.py:569-575`). Built by `expert_layout` (`iq_pack.py:429-473`):

```
# strata native experts v3: layer gu_type d_type offset blob_bytes gate_off up_off down_off [shard] (n_expert <E>, total <bytes>; absolute offsets in <shard 1>, or in the named shard beside it)
<layer> <gu_type> <d_type> <offset> <blob_bytes> <gate_off> <up_off> <down_off> [<shard file name>]
```

| Column | Meaning |
| --- | --- |
| `gu_type`, `d_type` | ggml type ids of gate/up (must be equal, `iq_pack.py:451-452`) and of down (may differ) |
| `offset` | the layer's start in the virtual `experts.bin` (sum of earlier layers' `blob_bytes * n_expert`) |
| `blob_bytes` | one expert's gate + up + down bytes in this layer |
| `gate_off`, `up_off`, `down_off` | absolute byte offsets of the three role tensors in their shard (`data_start + tensor offset`, per role's own shard, `iq_pack.py:459-460`) |
| shard | empty when the layer is in the `--gguf` shard, else the shard's file name |

When one layer's three roles sit in different shards the header says `v4` and the shard column of that layer is
`gate,up,down` (an empty field meaning the `--gguf` shard) (`iq_pack.py:456-468`). Every other pack stays v3 byte
for byte. The engine refuses a version above `kExpertLayoutVersion` = 4 (`include/strata/kernels/cpu/expert_layout.hpp:80`,
`src/kernels/cpu/expert_layout.cpp:256-266`) and takes `n_expert` from the header, so a pruned model (the Coder,
256 experts) is read correctly.

Formats are per layer: in the upstream golden copy for IQ3_XXS, layer 0 is IQ2_XS gate/up (17) with IQ4_NL down
(20), layer 1 IQ2_XXS (16) with Q2_0 down (42) (`tests/data/native_experts/iq3_xxs.txt`, a v2 file; the other
golden files are q2_0, iq2_xs, iq3_s, coder-iq1_m and swift-iq2_xs, read by `tests/core/expert_layout_test.cpp`).

### 1.4 `experts.bin` and `experts.bin.src.json` (optional)

With `--experts-bin`, per layer, `n_expert` blobs of `[gate rows | up rows | down rows]`: the raw GGUF slices
concatenated, no relayout (`iq_pack.py:530-533`, `586-593`). The engine reads this file instead of the GGUF when it
exists (needed by setup's low-RAM mode, `setup.py:4190-4193`, and for HIP's mmap path, see
[docs/AMD_HIP.md](https://github.com/Niko1221/Strata/blob/6f32ec070f23ced9f50e704d854d775da52591ab/docs/AMD_HIP.md)).

The sidecar (`experts_source`, `iq_pack.py:476-483`) is `{"schema": 1, "shards": [{"name", "size"}...],
"native_experts_sha256", "bytes"}`. An existing `experts.bin` is reused only when its size, the sidecar and six
sampled blobs (first and last expert of the first, middle and last layers) all match (`iq_pack.py:528-547`).

### 1.5 `conversions.json`

Schema 1 (`iq_pack.py:334-339`): `{"schema": 1, "tool": "tools/iq_pack.py", "compat_bf16", "source_shards":
[{"name", "size"}], "tensors": [...]}` where each tensor record has `name`, `shard`, `src_type`, `dst_type`,
`method`, `exact`, `max_abs_err`, `source_sha256` (sha256 of the source bytes) (`iq_pack.py:321-324`).

### 1.6 `compat-bf16.json`, `extra.bin`

- `compat-bf16.json` (only with `--compat-bf16`): `{"source", "rounding": "nearest-even", "tensors": [{"name",
  "source_type", "bytes"}]}`, listing only the conversions that rounded (`iq_pack.py:354-359`).
- `extra.bin` (only with `--base`): raw BF16 tensors that are float in this model but quantized in the base pack
  (the docstring names `blk.1.ple_key`), 64-byte aligned, index file id 3 (`iq_pack.py:401-417`). With `--base`,
  `dense.bin` is a hard link (or a copy) of the base pack's.

### 1.7 `tokenizer/`

Written by `strata_tokenizer.extract` (`tools/strata_tokenizer.py:270-298`):

| File | Content |
| --- | --- |
| `vocab.json` | token string -> id |
| `merges.txt` | merges in rank order, one `left right` per line |
| `token_type.json` | GGUF `tokenizer.ggml.token_type` list (3 = CONTROL, 4 = USER_DEFINED) |
| `tokenizer.json` | `model` ("gpt2"), `pre`, `vocab_size`, `n_merges`, `special_ids`, `add_bos_token` (false), `pre_pattern` (the transcribed qwen35 regex), `pre_pattern_source` |
| `chat_template.jinja` | the GGUF's `tokenizer.chat_template`, when present (fine-tunes differ) |

The server and the test scripts rebuild a `Tokenizer` from `vocab.json`, `merges.txt` and `token_type.json`
(`tools/calibrate.py:114-120`, `tools/batch_test.py:26-34`).

## 2. Canonical Q2_0 pack (`tools/strata_pack.py`, `tools/pack_layer.py`, `tools/pack_index.py`)

```
<pack>/
  experts.bin     48 layers x 512 experts x 1,382,400 B  (pack_layer.build)
  experts.json    pack_layer's own manifest of the arena
  dense.bin       every non-expert tensor except token_embd, canonical planes
  embd.bin        token_embd.weight, canonical planes
  manifest.json   strata-pack format_version 1
  index.txt       pack_index.py: 19 columns, "strata pack index v3"
  tokenizer/      strata_tokenizer.py (setup runs it separately)
```

### 2.1 Expert blob (`pack_layer.py`)

One expert is exactly 1,382,400 bytes, asserted at import (`tools/pack_layer.py:40-51`), for Flash-Next's geometry
H = 2560, FF = 640, 512 experts, Q2_0 (64-element blocks of 18 bytes):

| Plane | Offset | Bytes | Layout |
| --- | ---: | ---: | --- |
| `gate_up_codes` | 0 | 819,200 | 1,280 rows of 640 B: rows interleaved g0, u0, g1, u1, ... |
| `down_codes` | 819,200 | 409,600 | 2,560 rows of 160 B |
| `gate_up_scales` | 1,228,800 | 102,400 | 1,280 x 40 FP16 block scales, same row order |
| `down_scales` | 1,331,200 | 51,200 | 2,560 x 10 FP16 |

Q2_0 codes and FP16 scales are copied unchanged, so decoding the pack equals decoding the GGUF bit for bit
(`pack_layer.py:10-12`). Interleaving gate and up rows lets one pass over the activation serve both
(`pack_layer.py:14-17`). Expert `e` is a contiguous run of 460,800 bytes in each GGUF role tensor, because the expert
index is the last GGUF axis (`pack_layer.py:19-20`). `experts.json` holds `blob_bytes`, `offsets` (the four plane
offsets), per-layer `offset` and the role tensors' GGUF offsets, `n_layers`, `total_bytes` (`pack_layer.py:72`,
`108-114`).

### 2.2 Canonical forms (`dense.bin`, `embd.bin`)

`strata_pack.py` stores each non-expert tensor in one of five canonical forms, defined by the `MAPPINGS` table in
`tools/canonical_xcheck.py:563-577`:

| Source type | Form | code bias | group | offset plane | codebook |
| --- | --- | ---: | ---: | --- | --- |
| Q2_0 | S2 (2-bit codes) | -1 | 64 | no | affine |
| Q3_K | S4 | -4 | 16 | no | affine |
| Q4_0 | S4 | -8 | 32 | no | affine |
| Q4_K | S4 | 0 | 32 | yes | affine |
| Q5_0 | S8 | -16 | 32 | no | affine |
| Q5_K | S8 | 0 | 32 | yes | affine |
| Q6_K | S8 | -32 | 16 | no | affine |
| Q8_0 | S8 | -128 | 32 | no | affine |
| IQ4_NL, IQ4_XS | S4 | 0 | 32 | no | IQ4NL table |
| F32, BF16 | P32 (values) | - | - | - | - |
| F16 | P16 (values) | - | - | - | - |

Value = `(code + code_bias) * scale [+ offset]` per group, or `KV_IQ4NL[code] * scale`. Codes are packed LSB-first,
`8/bits` per byte, the Q2_0 convention for every form (`strata_pack.py:60-76`). Each plane (codes, scales, offsets,
or values) starts on a 64-byte boundary (`strata_pack.py:43`, `114-120`). Scales are FP16 when the round trip is
exact, else FP32, recorded per tensor (`choose_scale_dtype`, `strata_pack.py:90-95`). BF16 sources are promoted to
F32 (P32) so the decode is exact (`canonical_xcheck.py:490-500`).

### 2.3 `manifest.json`

`{"format": "strata-pack", "format_version": 1, "source": {"shard1", "shard2", "shard1_sha256"?,
"shard2_sha256"?}, "n_layers", "align": 64, "codebooks": {"IQ4NL": [...]}, "tensors": {name: entry},
"experts": {...}, "n_experts_per_layer": 512, "files": {...}, "shard2_tensor": {...}}`
(`strata_pack.py:214-277`). A tensor entry carries `name`, `source_type`, `form`, `codebook`, `code_bias`,
`has_offset`, `block_elems`, `block_bytes`, `group_elems`, `shape`, `source_offset`, `elements`, `file`, and either
`values` + `values_fp16` or `codes`/`scales`/`offsets` (each `{offset, bytes}`) + `code_bits`, `scales_fp16`,
`offsets_fp16`. `shard2_tensor` records where `per_layer_token_embd.weight` (the PLE table) sits in shard 2; the table
is not copied. The source hashes are absent after `--skip-hash`, which is how setup builds.

### 2.4 `index.txt` (canonical, `pack_index.py`)

Header and rows (written at `tools/pack_index.py:239-245`; the docstring's column list, lines 44-46, stops at
`scales_fp16` and omits the 19th column `act_kind`):

```
# strata pack index v3  --  generated by tools/pack_index.py; do not hand-edit
# align 64 pool <engine pool bytes> tensors <n>
# name file kind src_off src_bytes dst_off dst_bytes ne0 ne1 code_bits code_bias group_elems codebook has_offset codes_bytes scales_bytes offset_bytes scales_fp16 act_kind
```

| Column | Meaning |
| --- | --- |
| `file` | 0 `dense.bin`, 1 `embd.bin`, 2 `experts.bin` (`FILE_ID`, `pack_index.py:77`) |
| `kind` | 0 VERBATIM, 1 BF16_IN_F32 (take the high 16 bits), 2 F32, 3 F16_IN_F32 (round to nearest even) (`pack_index.py:78`, `204-221`) |
| `src_off`, `src_bytes` | the tensor's span in the pack file (all planes, which must be contiguous and in codes, scales, offsets order, `pack_index.py:139-159`) |
| `dst_off`, `dst_bytes` | its place and size in the engine's arena (aligned to `align`) |
| `ne0`, `ne1` | shape, `ne0` contiguous |
| `code_bits`, `code_bias`, `group_elems`, `codebook` (1 = IQ4NL), `has_offset` | the S-form decode parameters |
| `codes_bytes`, `scales_bytes`, `offset_bytes` | engine-form plane sizes; scales and offsets are always 4 bytes per entry in the engine, FP16 ones are widened at load (`pack_index.py:181-183`) |
| `scales_fp16` | whether the pack's scale plane is 2 bytes wide |
| `act_kind` | 0 = the weight's activations are quantized as Q8_0 (Q2_0, Q4_0, Q5_0, Q8_0, IQ4_NL), 1 = Q8_K (K-quants, IQ4_XS) (`pack_index.py:86-91`) |

BF16 and F16-in-F32 tensors are re-rounded to 16 bits in the engine (kinds 1 and 3), which upstream's docstring
measures as 1.374 GiB of the 5.305 GiB dense file (`pack_index.py:16-19`).

## 3. MTP draft layer

### 3.1 Fetch directory (`tools/mtp_fetch.py`)

```
<mtp>/
  mtp-inventory.json   {"repo", "total_bytes", "tensors": [{name, shard, dtype, shape, start, end, bytes}]}
  mtp-inventory.md     the same as a Markdown table
  mtp-manifest.json    [{...inventory row, "file": "tensors/<name>.bin", "sha256"}]
  tensors/<name>.bin   one raw file per mtp.* tensor (31 for the pinned revision)
  tensors/verified.json  {name: [size, mtime_ns, sha256]} for tensors that passed `verify`
```

(`tools/mtp_fetch.py:177-204`, `207-256`, `259-289`.)

### 3.2 MTP GGUF (`tools/mtp_pack.py`)

A GGUF with `general.architecture` = `qwen4exp-mtp`, written with llama.cpp's gguf-py `GGUFWriter`, and keys
`strata.mtp.source`, `strata.mtp.source_sha256` (sha256 of the sorted name -> sha256 map), `strata.mtp.expert_format`,
`strata.mtp.expert_quantizer` (`tools/mtp_pack.py:144-149`). Tensors keep the checkpoint names (`mtp.*`): 1-D norms
F32, other dense tensors BF16, the two fused expert tensors in the chosen format (`mtp_pack.py:151-180`). A
`<out>.report.json` lists each tensor's format and bytes.

### 3.3 Runtime directory (`tools/mtp_rt.py`), loaded with `--mtp`

| File | Content |
| --- | --- |
| `experts.bin` | 512 blobs of 1,382,400 bytes in the canonical blob layout of section 2.1 (`blob_of`, `tools/mtp_rt.py:48-58`) |
| `dense.bin` | every non-expert tensor, each 256-byte aligned: ten large projections as Q8_0, norms as F32 with `+1` applied, the rest BF16 (`mtp_rt.py:76-103`) |
| `dense.txt` | one line per tensor: `name kind rows cols offset bytes`, `kind` in `q8_0`, `bf16`, `f32`; names without `mtp.` and `layers.0.` |
| `draft_vocab.bin` | copied in by setup from `data/` (section 5) |

The engine reads them in `src/core/mtp.cpp:164-205` and `src/core/mtp.cpp:437-440`.

## 4. Expert-cache profile (`expert-profile.bin`, `tools/make_profile.py`)

Little-endian (`tools/make_profile.py:54-63`):

```
"STRP"
u32 version (1), u32 n_layers, u32 n_expert, u32 slots, u32 n_ranked     (slots == n_ranked when written here)
n_ranked x { u16 layer, u16 expert }                                     the ranking, best first
n_layers x n_expert x i32                                                slot of each (layer, expert), -1 if unranked
```

The engine's reader checks the magic, refuses a profile whose layers x experts differ from the model, and refuses
`n_ranked > slots` (`src/core/expert_cache.cpp:30-56`). The engine writes the same format with
`--expert-profile-save` (`include/strata/core/expert_cache.hpp:65`, tested byte for byte against
`make_profile.write_profile` in `tests/core/expert_profile_save_test.cpp`).

**Routing trace** (input of `make_profile.py`), written by `strata generate --dump-routing FILE` and by the serve
path: per token per layer, `i32 layer, i32 k, k x i32 expert id, k x f32 weight` (`src/program/generate.cpp:791-800`;
the serve path writes zero weights, read as unit weights).

## 5. Draft vocabulary subset (`draft_vocab.bin`)

A flat array of little-endian int32 token ids, no header (`tools/draft_vocab.py:106`, `140`); the base ids first in
their order, added ids after in id order. The engine reads `<mtp>/rt/draft_vocab.bin` when the draft layer binds
and computes draft logits over those rows only (`src/core/mtp.cpp:437-440`).

| `tools/ple_fp8_pack.py` | `strata-ple` | `per_layer_token_embd.weight`, ne = [160, rows] | I8 (24) holding FP8 E4M3 bytes | `strata.ple.format` = `f8_e4m3`, `strata.ple.scale` (F32) | the PLE GGUF (`src/kernels/ngram.cpp:197`) |

Both are GGUF v3 with 32-byte alignment, the header written by hand and the bytes copied straight from the

## Gotchas

- Two writers of `index.txt` produce the same 19 columns but different header comments: `pack_index.py` writes a
  third `# name file kind ...` line and two spaces around `--`; `iq_pack.py` does not. The engine only parses the
  `# align` line.
- `native_experts.txt` is the completion marker: setup checks for it (`setup.py:4185`). `iq_pack.py` deletes it
  before publishing a new `dense.bin`/`index.txt` (`iq_pack.py:343`), so an interrupted run leaves a pack setup sees
  as unfinished. The canonical pack has no such marker; setup checks `index.txt` and `experts.bin`
  (`setup.py:4176`).
- A blob of 1,382,400 bytes is a property of Flash-Next's geometry (H 2560, FF 640, Q2_0). `pack_layer.py` and
  `mtp_rt.py` hardcode it.
- `experts.bin` in a native pack takes precedence over the GGUF; a stale one is detected by the sidecar and the
  sampled blobs (section 1.4), and without a sidecar only a warning is printed (`iq_pack.py:548-554`).

## In UnbiasedStrata

The fork keeps these formats for Qwen3.8-Flash-Next and extends them for Qwen3.6-35B-A3B: `iq_pack.py` gains a
second FORM table, copies `expert-profile.bin` into the pack, and leaves the `-MTP` draft block out of the trunk
pack; a new `mtp_qwen36_pack.py` writes a different draft-pack format with `mtp.json` (fork commits e41dfc7,
7f92fa8). See the fork's [pack-format.md](../../codebase/tools/pack-format.md).
